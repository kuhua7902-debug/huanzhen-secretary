# 幻帧 Agent 架构说明

> 本文档描述**当前代码的真实结构**，与早期版本（「科吉 / Keji」时期）的架构图已有较大差异。
> 最后核对：2026-09。

---

## 一、这是什么

Windows 上的**本地 / 局域网多用户 AI 助手**：浏览器打开即用，支持多账号、角色权限、团队共享文件夹、管理员后台、知识库、数据分析、桌面自动化与语音交互。

- 技术栈：FastAPI + 原生 JS SPA（零构建） + vendored 的 [nanobot](https://github.com/HKUDS/nanobot) Agent 引擎
- Agent 引擎：`nanobot/`（HKUDS，MIT）。幻帧在其上增加了 Web 前端、多用户权限、团队工作区、桌面控制、语音等能力
- 许可：幻帧自有代码 MIT（见 `LICENSE`），第三方组件见 `THIRD_PARTY_NOTICES.md`

> **命名说明**：产品原名「科吉 / Keji」，后更名为「幻帧 / Huanzhen」。因此代码中仍可见大量
> `keji` 标识（模块名 `KejiAdapter`、数据库文件 `data/keji.db`、ChromaDB collection
> `keji_documents`、日志 logger `keji.*`）。
> **环境变量两套名字都支持**：`HUANZHEN_*` 优先，`KEJI_*` 兜底（见 `core/security/secrets.py::ENV_ALIASES`）。

## 二、请求主链路

```
浏览器 (web/index.html + web/js/*.js)
   │  POST /chat/stream          SSE: data: {json}\n\n
   ▼
main.py
   │  resolve_chat_ids()      → nanobot session key = "user:{uid}:{conv_id}"
   │  set_request_context()   → 把 user_id/role 放进 contextvars（权限判定的唯一依据）
   ▼
nanobot/adapter.py :: KejiAdapter
   │  _build_msgs()                  系统提示 + 沙箱目录 + 角色提示 + 已激活技能 + 历史
   │  _prepare_session_for_chat()    超阈值先自动压缩上下文
   ▼
nanobot/agent/runner.py :: AgentRunner.run()
   │  hook = CompositeHook([SSEHook, RolePermissionHook, ComplianceHook])
   │  每轮：上下文治理 → 调 LLM → 若有 tool_calls → 执行工具 → 回到循环
   ▼
ToolRegistry（lazy_tools：9 个直调工具 + web_search + __tool__ 万能分发器）
   ├── nanobot 内置：filesystem / shell / search / web / selfcheck
   ├── KejiTool × 65：adapter_tools.TOOL_DEFS → core/*.py 里的函数
   └── MCP 工具：npx / node 子进程，前缀 mcp_{server}_
   ▼
SSE 事件：thinking / think_token / answer / system_notice / error / done
         以及 ComplianceHook 另发的 selfcheck_start / selfcheck_result
```

### 关键设计点

1. **身份靠 `contextvars` 传递**。`core/security/context.py` 的 `RequestContext` 保存
   `user_id`/`role`，在 `main.py` 写入；工具在线程池里执行时仍能读到（`asyncio.to_thread`
   会复制上下文）。**任何绕过 `set_request_context()` 的入口（如语音、IM 桥接）都会丢失
   角色信息**，从而只受全局文件沙箱约束——这是有意保留的行为，但必须在新增入口时显式设置。

2. **懒加载工具表**。`_build_tools()` 注册全量 75 个工具（供执行）；
   `_build_lazy_tools()` 只把 9 个高频工具 + `web_search` + `__tool__` 交给模型，
   其余全部通过 `__tool__(tool, arguments)` 分发。目的是压缩 function-calling 定义体积，
   避免模型面对上百个函数定义而过载。

3. **权限与审计都挂在钩子上**，而不是散落在各工具里：
   - `RolePermissionHook`：执行前剔除角色不允许的 tool_calls，并注入 `[权限限制]` 说明
   - `ComplianceHook`：复杂工具前跑系统自检；生成数据交付物后强制要求 `verify_output`
   - `Runner._execute_tools()`：统一上报审计（无论走 `tool.execute` 还是 `registry.execute`）

## 三、两个引擎

项目里存在两套 Agent 执行链，**Web 走第一套，其余入口走第二套**：

| | **nanobot 引擎（主线）** | **CoreAgent（legacy）** |
|---|---|---|
| 实现 | `nanobot/agent/runner.py` | `core/agent.py` |
| 工具调用 | 原生 function calling + `__tool__` | 从文本里解析 `<tool_call>` / JSON |
| 工具注册表 | `nanobot.agent.tools.registry.ToolRegistry` | `core/tools.py` 的 `_tool_registry` 字典 |
| 工具执行 | 进程内 `asyncio.to_thread` | 每次调用 fork 一个 `cli.py` 子进程 |
| 模型 | 单一 provider，进程启动时确定 | `ModelRouter`，支持多模型 + 视觉模型 |
| 用于 | **Web 界面** | 语音、个人微信、企业微信、CLI |

> ⚠️ **两套注册表是同一批函数的两个「真相」**：`@register_tool` 装饰器（源文件内）供 legacy 用，
> `nanobot/adapter_tools.py` 的 `TOOL_DEFS` 供 Web 用。
> 历史上两者参数名漂移，导致 6 个工具在 Web 路径必然 `TypeError`。
> `tests/test_tool_schema.py` 现在会逐一比对 schema 与真实函数签名来防止再次漂移。

### 引擎层未被使用的部分

`nanobot/agent/loop.py`（`AgentLoop`）是 nanobot 的**产品编排层**——负责 MessageBus、渠道、
定时任务、心跳、记忆整理（Consolidator / Dream）。**幻帧没有走它**，因此以下代码在当前部署中
不会执行：

- `nanobot/channels/`（15 个渠道适配器，仅飞书桥接被接上且默认关闭）
- `AgentLoop` 的 bus / cron / heartbeat / dream / autocompact 编排
- `nanobot/cli/`、`nanobot/api/server.py`
- `nanobot/templates/` 下的重复模板

这意味着「定时任务」「长期记忆 Dream 整理」「子代理」等能力**代码存在但未启用**。
若后续需要这些能力，正确做法是把 `AgentLoop` 接进来复用，而不是继续在 `core/` 里另写一套。

## 五、安全模型

| 关注点 | 机制 | 位置 |
|---|---|---|
| 认证 | JWT（bcrypt 存密码）+ 可选服务 API Key | `core/security/auth.py`, `users.py` |
| 角色 | admin / member / readonly | `core/security/permissions.py` |
| 工具授权 | **fail-closed 白名单**：只读账号仅 `READ_ONLY_TOOLS` 放行，未知工具默认拒绝 | 同上 |
| 文件沙箱 | 所有工具的路径都要过 `assert_path_allowed`，并按角色限制到共享/个人目录 | `core/path_policy.py`, `core/workspace.py` |
| 命令执行 | `run_command` 有危险命令黑名单；`open_application` 已改为不经 shell 直接 `Popen` | `core/desktop_tools.py` |
| 归档解压 | tar 使用 `filter="data"` 并回退到手写安全解压，防 `../` 越界写 | `core/archive_tools.py` |
| 审计 | 工具调用与文件访问写 `logs/audit.jsonl` + SQLite `audit_events` | `core/security/audit.py` |
| 敏感数据 | 数据库配置密码用 Fernet 加密（密钥由机器名派生） | `core/routes.py`, `core/database/db.py` |
| 急停 | 进程级 `threading.Event`，GUI 工具在每个操作前检查 | `core/gui_abort.py` |

### 已知边界（有意保留，需知情）

1. **`run_code` / `exec` 不是内核级隔离**。`run_code` 注入的沙箱只替换了内建 `open()`，
   子进程里的 `os.remove` / `shutil.rmtree` / `subprocess` 不受约束；
   `exec` 的 OS 级 sandbox 在 Windows 上不可用（只有命令守卫 + 工作目录校验）。
   因此**不要把 `run_code` 暴露给不可信用户**，生产环境应配合容器/低权限账号运行。
2. **语音与 IM 桥接入口没有登录用户**，`resolve_current_user()` 返回 `None`，
   角色限制不生效，只剩全局文件沙箱。新增入口时请显式调用 `set_request_context()`。
3. **GUI 急停是进程级全局标志**，同一台机器上多个会话共享，无法按会话隔离。

## 六、开发与测试

```powershell
# 安装开发依赖（在已部署的 venv 上执行）
venv\Scripts\python.exe -m pip install -r requirements-dev.txt

# 运行测试
venv\Scripts\python.exe -m pytest tests -q

# 启动服务（带控制台，便于排错）
venv\Scripts\python.exe main.py
```

改前端时注意：`main.py` 给静态资源加的 cache-buster 是**每次请求重新生成的时间戳**，
因此刷新页面必定拿到最新资源（代价是每次刷新都重下约 250KB）。这是刻意的取舍——
开发期省去手动清缓存，代价是牺牲浏览器缓存。
