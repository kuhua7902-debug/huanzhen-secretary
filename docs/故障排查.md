# 故障排查手册

> 部署或使用幻帧遇到问题时，**先做这一步**：

```
双击  诊断.bat            （或命令行：venv\Scripts\python.exe scripts\doctor.py）
```

它会逐项检查运行环境、依赖、配置、端口、数据库、MCP，并对每个问题给出**具体修复命令**。
绝大多数问题能在这一屏里定位。

---

## 一、启动类问题

### 1.1 双击启动脚本「一闪而过」，服务没起来

**原因**：脚本在启动前就失败了，窗口来不及看清。

**排查**：
```powershell
cd 项目目录
venv\Scripts\python.exe scripts\doctor.py      # 看有没有 ERROR 项
venv\Scripts\python.exe main.py                # 前台启动，错误直接打在屏幕上
```

**常见原因**：

| 现象 | 原因 | 修复 |
|---|---|---|
| 提示未找到 venv | 还没部署 | 双击 `一键部署.bat` |
| 提示未找到 .env | 配置缺失 | 双击 `启动幻帧.bat` 会引导生成，或 `诊断.bat --fix` |
| Python 版本过低 / 非 64 位 | 环境不符 | 装 64 位 Python 3.12 后重新部署 |
| `ModuleNotFoundError: xxx` | 依赖没装全 | `venv\Scripts\python.exe -m pip install -r requirements.txt` |

### 1.2 浏览器打开了，但是白屏 / 无法访问此网站

**原因**：浏览器打开得太早（服务还没就绪），或服务已退出。

新版 `启动幻帧.bat` 会**轮询等待服务真正就绪**后再打开浏览器，一般不会再有这个问题。
若仍出现：

```powershell
# 1) 确认服务在监听
Get-NetTCPConnection -LocalPort 8000 -State Listen

# 2) 确认健康接口
curl http://127.0.0.1:8000/health
# 期望：{"status":"healthy","engine":"nanobot"}

# 3) 没起来就看启动日志
Get-Content logs\launcher.err.log -Tail 50
```

> **首次启动要 10~40 秒**：服务需要连接 MCP 服务器（npx/node 子进程）后才完全就绪。

### 1.3 提示「幻帧似乎已经在运行了」

这是**单实例保护**在生效（防止两个实例抢同一个数据库）。

> 常见触发场景：双击 `启动幻帧.bat` 没反应，于是又双击一次——
> 而第一次其实**正在启动中**（服务需 10~40 秒才监听端口），端口检测此时还拦不住。

按提示二选一：

```powershell
# 确认它确实在跑 → 直接用，或先停再启
#   浏览器打开 http://127.0.0.1:8000/
#   重启：双击 停止服务.bat  →  再双击 启动幻帧.bat

# 确认没有实例在跑（例如上次被强制结束、留下僵尸锁）
#   方式一：删除锁文件后重试
Remove-Item data\.huanzhen.lock -ErrorAction SilentlyContinue
#   方式二：强制启动（忽略锁）
$env:HUANZHEN_FORCE_START = "1"; .\venv\Scripts\python.exe main.py
```

> 正常情况下进程被强杀留下的锁会被**自动接管**，只有"PID 恰好被别的进程复用"这种
> 极小概率情况才需要手动处理——所以提示里一定给了绕过办法，不会把你卡死。

### 1.4 端口 8000 被占用

```powershell
# 看是谁占用
Get-NetTCPConnection -LocalPort 8000 -State Listen

# 结束占用进程（通常是上一次没退干净的幻帧）
Get-NetTCPConnection -LocalPort 8000 -State Listen |
  ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }
```

**注意**：直接重复双击 `启动幻帧.bat` 不会起第二个服务——脚本检测到端口已监听时会直接打开页面。

### 1.5 想换端口

```powershell
$env:HUANZHEN_PORT = "8080"
venv\Scripts\python.exe main.py
```
或写进 `.env`：`HUANZHEN_PORT=8080`

## 二、登录与账号

### 2.1 网页打不开 / 提示「未授权：请登录」

说明鉴权已启用，需要登录。默认管理员用户名见 `config.yaml`：

```yaml
security:
  bootstrap_admin:
    username: admin
```

密码来自 `.env` 的 `HUANZHEN_ADMIN_PASSWORD`。

> ⚠️ `bootstrap_admin` **只在数据库里没有任何用户时**才执行。
> 已经初始化过的部署，改 `.env` 里的密码**不会**改变已有账号的密码。

### 2.2 忘记管理员密码

```powershell
venv\Scripts\python.exe scripts\reset_password.py
```

### 2.3 提示「尝试过于频繁」/「失败次数过多」

这是**登录失败限流**（防暴力破解）在生效，不是故障。

- 同一 IP 或同一用户名在 5 分钟内失败 5 次后开始锁定，锁定时间阶梯上升（30s → 60s → … 封顶 15 分钟）
- **正常登录成功会立即清零**
- 按提示等待即可；如果你确实忘了密码，用 `scripts\reset_password.py` 重置，不要反复试

阈值可用环境变量调整（一般不需要）：

```env
HUANZHEN_LOGIN_WINDOW=300       # 统计窗口（秒）
HUANZHEN_LOGIN_MAX_FAILS=5      # 触发锁定的失败次数
HUANZHEN_LOGIN_MAX_LOCK=900     # 单次锁定时长上限（秒）
```

### 2.4 想允许本机免登录（仅内网调试用）

```yaml
security:
  allow_localhost_without_auth: true     # ⚠️ 生产/局域网共享场景不要开
```

## 三、模型与对话

### 3.1 对话报错、一直转圈、或提示密钥无效

**逐项确认**：

1. `.env` 里对应模型的 key 是否填写（doctor 会直接告诉你）
2. `config.yaml` 的 `models.default` 指向的模型，其 `api_key` 是否能解析出值
3. 网络能否访问模型服务（国内访问 OpenAI 需要代理；DeepSeek / 智谱 / 通义千问可直连）

```yaml
models:
  default: deepseek          # 必须是下面已配置的某个键
  deepseek:
    base_url: https://api.deepseek.com
    api_key: ${DEEPSEEK_API_KEY}    # ← 对应 .env 里的 DEEPSEEK_API_KEY
```

### 3.2 想换默认模型

改 `config.yaml` 的 `models.default`（可选值：`deepseek` / `openai` / `zhipu` / `ollama` 等），
或在网页对话框右下角按会话临时切换。

### 3.3 想用本地模型（不联网、不外传数据）

```yaml
models:
  default: ollama
  ollama:
    base_url: http://localhost:11434
    model: qwen2.5:7b
```
先安装 [Ollama](https://ollama.com) 并 `ollama pull qwen2.5:7b`。

## 四、知识与扩展

### 4.1 知识库检索不到结果

**原因**：向量嵌入依赖本地 Ollama（默认模型 `nomic-embed-text`）。
未安装时索引会退化为**零向量**，检索自然无结果。

```powershell
ollama pull nomic-embed-text     # 安装并拉取嵌入模型
# 然后重新索引：网页「知识库」页 → 重新索引；或调工具 index_knowledge(path)
```

### 4.2 MCP 外部工具（文件/Excel/图表等）不可用

```powershell
node -v      # 需要 Node.js 18+
npx -v
```

未安装 Node.js 时：**内置工具照常可用**，只是 MCP 那部分缺失。
确认哪个服务器连不上：网页「设置 → MCP 服务」面板会列出「已连接 / 未连接」。

用不到的服务器可在 `config.yaml` 的 `mcp_servers` 段删掉，减少启动时间。

## 五、桌面自动化

### 5.1 提示「未安装 pyautogui / uiautomation」

```powershell
venv\Scripts\python.exe -m pip install pyautogui pillow uiautomation pywin32 pyperclip
```

### 5.2 桌面自动化很慢 / 一直在截图

**这是设计上的分层策略**，不是故障：

```
第 0 级 应用级 API（Office/WPS COM）  ← 最快，生成文档类任务优先走这里
第 1 级 UI Automation 控件树           ← 通用软件的精确点击
第 2 级 浏览器 puppeteer MCP           ← 网页
第 3 级 视觉 + 坐标点击                ← 兜底，最慢
```

如果某个软件（如 WPS 首页）界面是**自绘的**，控件树读不到内容，会退到视觉兜底——
这时用「生成文档」类任务（`office_create_document`）会比模拟点击快几十倍。

### 5.3 想让服务运行时能操作桌面

服务若以**后台无窗口**方式运行（`启动幻帧.bat`），GUI 工具仍可工作；
但**锁屏状态下**鼠标键盘操作会失败，请保持桌面解锁。

## 六、数据与安全

### 6.1 历史对话不见了

**常见原因**：`config.yaml` 里的 `database.path` 写错，导致程序用了另一个库。

```yaml
database:
  path: data/huanzhen.db     # 只有该文件已存在时才会被采用（避免悄悄新建空库）
```

用 doctor 的「数据与扩展 → 数据库可读」一项确认当前实际使用的库与用户/对话数量。

### 6.2 密钥怎么轮换

1. 到各平台（DeepSeek / 智谱 / OpenAI 等）**吊销旧 key 并签发新 key**
2. 更新 `.env`
3. 重启服务（`启动幻帧.bat`）

> 项目历史提交中曾出现过明文密钥（详见 `SECURITY.md`）。
> 若你是从公开仓库克隆的，请**务必轮换**。

### 6.3 管理员密码 / JWT 密钥丢失会怎样

- **JWT 密钥**：默认存在 `data/security/jwt_secret`。**该文件丢失会导致所有用户立即掉线**（需重新登录）。
  生产环境建议在 `.env` 显式设置 `HUANZHEN_JWT_SECRET`（备份它）。
- **管理员密码**：用 `scripts\reset_password.py` 重置。

### 6.4 数据备份与恢复

**备份**（数据全在 `data/huanzhen.db`，误删即全丢，务必定期备份）：

```powershell
# 双击 备份.bat，或命令行：
venv\Scripts\python.exe scripts\backup.py            # 备份一次
venv\Scripts\python.exe scripts\backup.py --list     # 查看已有备份
venv\Scripts\python.exe scripts\backup.py --keep 14  # 保留最近 14 份
```

- 产物：`data\backups\huanzhen-backup-<时间戳>.zip`（含数据库、`config.yaml`、`security/*`、`MANIFEST.txt`）
- **服务启动时每天会自动备份一次**（同一天不重复）
- 默认保留最近 **7** 份
- ⚠️ **备份不含 `.env`**（含 API 密钥），请自行单独保管，否则换机后无法恢复模型密钥

**恢复**：

```powershell
# 1) 先停服务
#    双击 停止服务.bat
# 2) 解压备份，把 huanzhen.db 覆盖到 data\ 目录
# 3) 需要时一并覆盖 config.yaml 与 data\security\*
# 4) 重新启动：双击 启动幻帧.bat
```

> 为什么不能直接复制 `data\huanzhen.db`？服务运行时数据库处于活动状态（可能有未落盘事务/WAL），
> 直接 copy 得到的文件可能损坏。本项目的备份走的是 **SQLite 官方备份 API**，生成的是**一致快照**。

### 6.5 数据越积越多 / 想清理旧记录

服务是常驻的，三类数据会随时间增长：`logs/audit.jsonl`、数据库 `audit_events` 表、`sessions/*.jsonl`。

内置**保留策略**（默认：审计 90 天、归档 365 天、会话 180 天、库审计 180 天）：

```powershell
# 先预演，看清会动到什么（不改动任何文件）
venv\Scripts\python.exe scripts\retention.py --dry-run

# 确认后执行
venv\Scripts\python.exe scripts\retention.py
```

- 网页端更方便：**设置 → 系统状态 → 数据保留**，有「预演」和「立即清理」两个按钮
- **服务启动时每月自动执行一次**
- 策略是**归档优先、删除兜底**：旧审计按月份压缩到 `logs/archive/audit-YYYY-MM.jsonl.gz`，
  到期才真正移除；**无法判定时间的记录一律保留**
- ⚠️ 命令行执行时若服务正在运行，归档期间极小概率丢新记录；**网页触发会加写入锁，更安全**

> 想知道当前占了多少：网页「系统状态」会显示库大小与磁盘剩余。

## 七、需要求助时，请提供这些信息

```powershell
# 1) 自检报告（把整屏复制下来）
venv\Scripts\python.exe scripts\doctor.py

# 2) 启动日志末尾
Get-Content logs\launcher.err.log -Tail 80

# 3) 版本信息
venv\Scripts\python.exe -c "import sys; print(sys.version)"
git log --oneline -1
```

> 复制日志前请**确认里面没有 API Key**（`.env` 不会写进日志，但工具参数可能包含敏感内容）。
